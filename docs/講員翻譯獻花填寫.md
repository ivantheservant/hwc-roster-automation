# 講員／翻譯／獻花填寫

講員、翻譯、獻花呢三個崗位系統**永遠唔會自動排人**（`Posts.AutoGenerate=FALSE`），
每一季都要幹事自己人手填。呢份文件講點樣用「準備工作 ▸ 填寫講員／翻譯／獻花」
呢個側邊欄工具。

---

## 點解呢三個崗位唔自動排

- **講員**：常任講員通常係牧師，客席講員可能每季度都唔同，唔係一個排班問題。
- **翻譯**：同上，而且未必每次都需要即時傳譯。
- **獻花**：由會友自行認獻，**唔係每週都有人**——呢個係同前面兩個最大嘅
  分別，見下面「獻花：可以留空」一節。

## 幾時填、喺邊度填

**建議喺「步驟 1：生成初稿」之後、「步驟 2：寄給堂委審閱」之前填**——堂委
收到嘅審閱信會附完整版 PDF，如果講員嗰欄成條空白，堂委第一個反應會係
「個系統排唔到」。

選單 ▸ 準備工作 ▸ **填寫講員／翻譯／獻花**，輸入 QuarterID，會開啟一個
側邊欄。

## 側邊欄點用

1. 一次過列晒呢一季**全部三個崗位**仲空著嘅格子（唔使逐個崗位開一次
   工具），逐格顯示：第幾週、日期、崗位名。
2. 如果呢個崗位過去出現過人選，格子上面會有幾個建議按鈕（依出現次數
   由多到少排序），撳一下就自動填入輸入格，唔使打字。
3. 打好名之後撳「儲存」，即時寫入職事表格子、`RosterAssignments` 與
   `AuditLog`。
4. **「全部儲存」按鈕**（第十四輪批次新增）：如果一次過打好晒多個格子，
   唔使逐格撳「儲存」，撳呢個掣會一次過儲存全部已經有輸入姓名嘅格子
   （未輸入嘅唔會被觸碰）。
5. 隨時可以關閉側邊欄，之後重新開啟會繼續顯示仲未填嘅格子——冇「一定
   要一次填晒」嘅壓力。

輸入嘅名字**唔強制**要出現喺 `NameMapping`（義工名單）入面。如果打嘅名
啱啱好完全符合某個義工嘅登記姓名，系統會自動連結佢嘅 `PersonID`（供日後
統計用）；打唔中就淨係記文字快照，兩種情況功能上完全一樣，都會正常顯示
喺職事表同 PDF 上。

## 獻花：可以留空

獻花由會友自行認獻，唔係每週都有人。側邊欄嘅獻花格子會有虛線邊框同
「可留空」嘅黃色標籤，提示你**唔使勉強填**。

**留空嘅做法就係唔撳「儲存」**——工具冇提供一個「明確標記呢一週冇人
認獻」嘅額外按鈕，因為「乜都唔做」已經係最終正確嘅結果：呢一格喺公開
職事表／個人專屬連結會顯示做完全空白（`Posts.EmptyDisplay=BLANK` 嘅
設計，見 `docs/GoogleSheetsAPI限制.md`），對外版面本身有一行圖例
「（空白）」解釋呢種空白係正常情況、唔係漏做，義工唔會誤會系統漏咗嘢。

## 填寫之後：唔會建立新版本、唔會影響其他人

**填寫講員／翻譯／獻花直接寫入目前最新版本，唔會建立新版本、唔會觸發
規則重新檢查、唔會推進 `QuarterStage`。** 呢個係刻意嘅設計：

1. 呢三個崗位完全唔受 `Eligibility`／硬規則約束，建新版本嘅意義（重新
   跑規則判斷）喺呢度用唔著。
2. 建新版本屬於「步驟 1」「步驟 3」呢類會推進流程狀態嘅動作，填寫補充
   資料唔應該連帶推咗 `QuarterStage`。
3. `ResendFlow.gs`（「步驟 5：改動後重發」）係按**每個人自己嘅派工組合**
   計 hash 判斷邊個要收到重發通知，唔係按版本號整個比對。填寫講員之後，
   只有嗰位講員自己嘅 hash 會變（佢應該收到通知，呢個係啱嘅），其他
   完全冇被呢次填寫觸及嘅人嘅 hash 完全唔會變，唔會被誤判成「內容改咗」
   而收到唔必要嘅重發信。

**如果呢一季已經正式發出過（Stage=OFFICIAL_SENT）之後先填**：側邊欄會
顯示提示，記得回選單執行「步驟 5：改動後重發」通知相關人士（例如新確定
嘅講員）。

## 常見問題

**Q：填錯咗個名，可以改嗎？**
A：直接重新打入正確嘅名再撳「儲存」，會覆寫原本嘅內容。如果係已經正式
發出之後先改，記得跑「步驟 5：改動後重發」通知嗰位講員／翻譯／獻花的人
（如果佢有登記電郵）。

**Q：想清空一個已經填咗嘅獻花格（例如原本認獻嘅人臨時取消），點做？**
A：呢個工具目前冇「清空」功能，只支援填新內容。要清空要直接去職事表
grid 工作表（`Roster_{QuarterID}_v{版本}`）手動刪走嗰格文字。

**Q：`Posts` 工作表要點設定，先可以用呢個工具？**
A：`Posts.PostName_TC` 要**逐字完全對應**「講員」「翻譯」「獻花」（三個
之中最少要有一個存在，工具先可以運作）；`Posts.EmptyDisplay` 建議
講員設 `PENDING`（顯示「（待填）」提示未填）、翻譯／獻花設 `BLANK`
（留空唔顯示提示文字）——呢個係本專案目前 seed 嘅預設值，唔需要另外設定。
