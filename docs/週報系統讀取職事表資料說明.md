# 週報系統讀取職事表資料說明

> 給「週報系統」（以及任何要讀職事表資料的程式）用。全部內容按程式碼核對（第八十二輪，`src/Constants.gs`、`src/RosterWriter.gs`、`src/StateSource.gs`、`src/SheetReader.gs`、`src/PublicRoster.gs`）。
> **本檔檔名不可以改**——週報系統由 GitHub 公開網址讀它：
> `https://raw.githubusercontent.com/ivantheservant/hwc-roster-automation/main/docs/週報系統讀取職事表資料說明.md`
>
> 公開 repo：本檔不含任何真實姓名、電郵、試算表 ID 或網址；例子一律用假名、PersonID。
> **交接必做**：之後每一輪如果改到下面任何一項資料（欄位、顯示字、版本規則、寄出狀態），同一輪要更新本檔，並在第 9 節加一行。

## 1. 一句總結

- 「這一季現在的正式內容」＝ `RosterVersions` 裏這一季 **VersionNo 最大** 那一版，在 `RosterAssignments` 裏 `QuarterID`＋`VersionNo` 相同的那幾行。
- **不要**讀職事表工作表（`Roster_<季度>_v<N>`）上的字：最新那一張上面可能有幹事**未儲存**的人手改動；舊版本那幾張會被系統還原或者被當作起點覆寫。
- 人名顯示用 `NameMapping.NameTC`（按 PersonID 對）；沒有 PersonID 的格只有名字（見第 4 節）。

## 2. 怎樣找「這一季最新的版本」

工作表 `RosterVersions`（第 1 行中文標題，第 2 行機器鍵，第 3 行起資料）：

| 機器鍵 | 意思 |
|---|---|
| `QuarterID` | 季度，例如 `2028T3`（年＋T＋第幾季） |
| `VersionNo` | 版本號，0 起。**同一季取最大值＝最新**（系統內部 `findLatestVersionNo()` 就是這樣做；`Quarters` 表沒有「現行版本」欄） |
| `SheetName` | 那一版的職事表工作表名（`Roster_<季度>_v<N>`）。只作顯示／連結用，不要讀它的格 |
| `Basis` | 這一版怎樣來的：`AUTO_GENERATE`（生成；`ParentVersionNo` 有值＝重新生成）、`FINE_TUNE`（人手改動後儲存）、`SUGGESTION`（接受〔請系統幫我調整〕的建議）、`REQUESTS_APPLIED`（套用修改申報）、`RESEND`（正式發出後套用申報）、`IMPORT`（由人手編好的職事表匯入），或者「以第 M 版作起點」這句中文（用舊版本作起點再儲存） |
| `ParentVersionNo` | 由哪一版改出來 |
| `ChangeCounts` | `manual=N;system=M;start=K`：人手改了 N 格、系統調整 M 格、以第 K 版作起點（K 可空）。舊版本可能空白 |
| `CreatedAt` | 建立時間（`yyyy-MM-dd HH:mm:ss`，時區見 `Config.SYS_TIMEZONE`） |
| `Status`／`Protected`／`WarningCount`／`CreatedBy`／`Notes` | 內部用，讀取方不需要 |

⚠️ 一季可以被「整季清走重來」（第八十二輪 IJ 組）或者測試重設：之後版本號由 0 重新開始，舊的 `RosterAssignments`／`RosterVersions` 行會被刪走。讀取方不要假設版本號只會上升、也不要長期快取舊版本的資料。

## 3. `RosterAssignments` 每一欄

一格（一個主日 × 一個崗位 × 一個位置）一行：

| 機器鍵 | 意思 |
|---|---|
| `QuarterID`、`VersionNo` | 屬於哪一季、哪一版 |
| `ServiceDateID`、`ServiceDate` | 主日（日期以試算表日期儲存；按 `Config.SYS_TIMEZONE` 轉成 `yyyy-MM-dd`） |
| `PostID`、`SlotIndex` | 崗位（對 `Posts.PostID`，中文名 `Posts.PostName_TC`）、第幾個位置（1 起） |
| `PersonID` | 名單上的人（對 `NameMapping.PersonID`）。**可以空白**（見第 4 節） |
| `PersonNameSnapshot` | 儲存那一刻的名字。有 PersonID 時只作參考（顯示請用 `NameMapping.NameTC`）；沒有 PersonID 時這就是唯一的名字 |
| `AssignSource` | 這一格怎樣來：`AUTO`（系統排）、`FINE_TUNED`（系統調整）、`FORCED`、`MANUAL`（人手：幹事在表上改、填講員／翻譯／獻花、申報指定）、`LOCKED`（預先鎖定）、`SKIPPED`（這一週跳過） |
| `RuleFlags` | 逗號分隔的規則代號（例如 `HARD_NO_AUTO_PREACHER`＝這個崗位不由系統排、`HARD_SPECIAL_SUNDAY_SKIP`＝這一週跳過）。用來分「空格」是哪一種，不是人 |
| `Locked`、`UpdatedAt`、`UpdatedBy`、`AssignmentID` | 內部用 |

合堂等特別安排的週，幹事人手清空不用的崗位：這些格 `PersonID`、`PersonNameSnapshot` 都空白，沒有 `RuleFlags`，讀取方當「未排定」。結構性不設只看 `RuleFlags`（`STRUCTURAL_NA_RULE_IDS`）。

### 3.1 哪些「名字」其實不是人

職事表工作表上會出現下面這些顯示字（可在 `Config` 改；括號內是預設值）。它們**不會**以 PersonID 出現；若在 `PersonNameSnapshot` 或工作表上見到，一律當空白：

- `GRID_PENDING_LABEL`（「（待填）」）：本來就要人手填的崗位（講員／翻譯／獻花等，`Posts.AutoGenerate=FALSE`）還沒有填
- `GRID_GAP_LABEL`（「⚠ 未能安排」）：系統應該排但排不出
- `GRID_NOT_APPLICABLE_LABEL`（「—」）：這一週這個崗位不設
- `GRID_SPECIAL_SKIP_LABEL`（「特殊主日」）：特別主日跳過
- 舊資料可能有的佔位字：「待確認」「另行安排」「-」「—」「－」「N/A」「n/a」（`GRID_PLACEHOLDER_TEXTS`）
- 特別主日由外部單位負責時，格內可能顯示該單位名稱（例如「英語堂」），同樣不是人

## 4. 沒有 PersonID 的格

- **名單以外的名字**（例如外請講員，崗位 `AutoGenerate=FALSE`）：`PersonID` 空白，`PersonNameSnapshot`＝幹事填的名字。
- **臨時幫手**（第七十五輪 CE 組）：幹事在職事表填了一個名單上找不到的名字，並勾了「這一季臨時幫手，不加入名單」。同樣 `PersonID` 空白、只有名字；沒有電郵、不計服侍次數。逐格決定記在 `CellDecisions` 工作表（讀取方不需要）。
- 讀取方：`PersonID` 空白而 `PersonNameSnapshot` 有字（而且不是第 3.1 節的顯示字）⇒ 照顯示那個名字。

## 5. 每週標題

- `ServiceDates.Title`：幹事在職事表「類型」欄改的每週標題（第七十五輪 CC 組）。**空白＝預設類型**（`ServiceDates.ServiceType`，例如「主日崇拜」）。
- `Config.SPECIAL_SUNDAYS_ENABLED`：預設 `FALSE`（第七十五輪 CC 組起特別主日拿走）。為 `FALSE` 時**不要再讀** `SpecialSundays` 工作表——它的內容不會影響職事表。

## 6. 人名與電郵

- 顯示名：`NameMapping.NameTC`（按 PersonID）。英文名 `NameEN`。
- 電郵：`NameMapping.Email`，由出席系統按會眾編號（`MemberNo`）自動更新（第七十七輪 EG 組）；`EmailSource`、`SyncedAt` 記錄來源和時間。幹事介面載入時、寄出之前都會同步一次。
- `NameMapping.PersonalLinkToken` 是個人專屬連結的 token，**不要**讀取或轉載。

## 7. 公開職事表（唯讀）

- 工作表 `PublicLinks`：一季一行，`FileUrl` 是公開職事表檔案的網址，`LastPublishedAt`／`LastPublishedVersion` 是最後發佈的時間和版本。
- 網址格式：`https://docs.google.com/spreadsheets/d/<檔案 ID>/preview`（`/preview` ＝ 沒有編輯工具列的唯讀顯示）。每次儲存新一版，系統會重新發佈到**同一個**網址。
- 一季被重設之後，公開檔不會刪除，但內容會清空並顯示「已重設」，等下次發佈再覆寫。

## 8. 正式發出狀態

- `Quarters.Stage`：`DRAFT`（初稿）、`REVIEW_SENT`（已寄審閱本）、`REQUESTS_APPLIED`（已儲存修改）、`OFFICIAL_SENT`（已正式發出給全體）。
  - 第八十二輪 IG 組起：正式發出不再要求先寄審閱本，可以由 `DRAFT` 直接到 `OFFICIAL_SENT`；正式發出之後再寄審閱本，Stage 仍然是 `OFFICIAL_SENT`。
- `SendLog`：每封信一行。`Stage` 是 `REVIEW`／`OFFICIAL`／`RESEND`；`Status` 有 `SENT`、`DRY_RUN`（測試模式只記錄）、`SKIPPED_NO_EMAIL`、`EXTERNAL`（匯入時聲明已在系統外寄出）等；`VersionNo` 是寄出的版本。
  - 「這一季有沒有正式發出過」：`SendLog` 有這一季 `Stage=OFFICIAL` 或 `RESEND`（或 `Status=EXTERNAL`）的行，或者 `Quarters.Stage=OFFICIAL_SENT`。
  - 正式發出之後也可能有 `Stage=REVIEW` 的行（〔寄給堂委／執事〕），它們不代表進度倒退。

## 9. 第六十三至八十四輪之中會影響讀取方的改動

| 輪次 | 改動 |
|---|---|
| 第六十三輪 | `AssignSource` 分「人手（`MANUAL`／`LOCKED`）」和「系統」；講員等人手崗位人手填的不算違規 |
| 第六十七輪 | 新 `Basis`：`IMPORT`（由人手編好的職事表匯入） |
| 第七十四輪 | 已通知過人的版本，講員／翻譯／獻花的改動要儲存成新一版才算數（不再即時寫入舊版本） |
| 第七十五輪 | 講員／翻譯／獻花一律在職事表直接填；名單以外的名字、臨時幫手只有名字沒有 PersonID；每週標題 `ServiceDates.Title`；`SPECIAL_SUNDAYS_ENABLED=FALSE`；新 `Basis`：`SUGGESTION`、「以第 M 版作起點」 |
| 第七十六輪 | 四個顯示字（待填／不設／特殊主日／未能安排）一律當空白比較 |
| 第七十七輪 | `RosterVersions.ChangeCounts`；舊版本工作表開啟時會被還原成那一版；電郵由出席系統按會眾編號更新 |
| 第七十八輪 | 用舊版本作起點的那張舊表，儲存新一版之後會被還原 |
| 第八十一輪 | 改動後重發以上一次正式發出／重發的版本做基準；新加入的人也算「安排有改動」 |
| 第八十二輪 | 用舊版本作起點再儲存一定建立新一版（`Basis`＝「以第 M 版作起點」）；正式發出不再要求先寄審閱本、Stage 可由 `DRAFT` 直接到 `OFFICIAL_SENT`；正式發出之後可以再寄審閱本（`SendLog` 有 `REVIEW` 行、Stage 不變）；幹事介面「整季清走重來」會刪走整季版本、版本號由 0 重新開始；〔請系統幫我調整〕會按排表偏好微調（產生的仍然是普通新版本） |
| 第八十四輪 | 讀取的資料沒有改動（只改幹事介面字眼和規則審閱表）；第 3 節更正中文崗位名欄為 `Posts.PostName_TC`，並說明合堂等特別安排的週人手清空的格（沒有 `RuleFlags`，當「未排定」） |
