# 個人連結頁面樣本（實際渲染結果）

呢份文件係**用虛構資料實際渲染出嚟嘅個人專屬連結頁面**，唔係樣板
原始碼。目的係喺 Ivan 新增 `access=ANYONE` 部署、正式開放俾冇
Google 帳戶嘅義工存取之前，先有人逐份讀過實際輸出——呢個係整個
專案第一次開放俾非白名單人士嘅入口，開放之前必須有人讀過。

產生方式：`node tests/render_personal_roster_samples.js`。頁面內容
讀自**真正嘅 `src/ui/PersonalRoster.html` 樣板檔案**（用自製嘅輕量版
GAS scriptlet 樣板引擎評估，見 `tests/helpers/gas_html_renderer.js`），
版面轉置用嘅係正式碼嘅 `transposeRosterForPublicView_()`
（`src/RosterWriter.gs`），「無效 token」／「季度不存在」兩種情況
直接呼叫正式碼嘅 `renderPersonalRosterError_()`（`src/WebAppPersonalLink.gs`）。

全部資料一律虛構：姓名用「周大文」「陳小明」「李美美」「馮小華」
「黃三」，`PersonID` 用 `P001`–`P005`，季度用 2099T1。

---

## 覆核結論（D3，詳細討論見 docs/系統範圍稽核.md 第十三輪批次階段 D）

逐項覆核四份輸出之後嘅結論：

1. **冇任何不應該公開嘅資訊洩漏**——四份輸出都冇出現電郵、
   `PersonID`、內部代號（`postId`／`personId` 等機器鍵完全冇出現
   喺輸出文字入面，只有 `postNameTC`／姓名呢類本來就係俾人睇嘅
   顯示文字）、規則違反標示、`Stage`、版本號以外嘅系統狀態。
   `versionNo` 本身有傳入 `data`，但樣板完全冇輸出佢，只用嚟
   組 `<title>`（`data.quarterId ?> 職事表`，唔含版本號）。
2. **「無效 token」同「季度不存在」兩種情況輸出完全一樣**——
   兩個情況都導向同一個 `renderPersonalRosterError_()`，證明
   `PERSONAL_LINK_INVALID_MESSAGE` 呢個中性錯誤訊息設計有效：
   訪客完全冇辦法從畫面分辨係邊一種原因，減少暴力嘗試 token
   嘅可乘之機。
3. **頁面完全冇任何會改動資料嘅路徑**——冇 `<form>`、冇
   `<input>`，唯一嘅互動元素係深色/淺色切換掣（純前端 CSS，
   `localStorage` 讀寫，唔改任何伺服器資料）。
4. **頁面完全冇輸出任何 `google.script.run` 呼叫**——樣板本身
   （`src/ui/PersonalRoster.html`）搜尋唔到呢個字串，四份實際
   渲染輸出一樣搜尋唔到。
5. **匿名訪客呼叫任何 `api*` 函式一律被拒絕**——`renderPersonalRosterPage_()`
   完全唔呼叫任何 `api*` 函式，個人連結呢條路徑本身唔經過
   `assertApiCallerAuthorized_()`（義工冇 Google 身分），呢個
   係刻意嘅設計（見 `WebAppPersonalLink.gs` 檔頭），唔係漏做
   ——安全性完全靠 token 本身唔可猜。呢一項嘅獨立驗證見
   `tests/webapp_access_guard.test.js`（鎖住全部 `api*` 函式
   第一行都係 `assertWebAppRequestAllowed_()`）同
   `tests/personal_link.test.js`（鎖住 `renderPersonalRosterPage_()`
   完全冇呼叫 `assertApiCallerAuthorized_()`）。

**冇發現任何安全或格式問題。**
