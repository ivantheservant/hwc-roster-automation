## 8. 這個 project 反覆出現的病（十月先讀，會省很多時間）

1. **「測試全綠，真環境出事」**——fixture 人手砌到真實 code path
   造不出的狀態。所有代表「系統寫出來的資料」的 fixture，
   必須經真實入口產生。
2. **一段寫得對的碼，上游判斷令它永遠行不到，等於沒寫過。**
3. **同一件事幾個入口做，總有幾個漏。** Audit 要**由資料那邊數起**
   （「誰會在這張表加行」），不是由你知道的函式數起——
   否則會像第五十二輪那樣漏了第五個入口。
4. **局部的壞不可以自動變成全域的停。**（自測機三次原地打轉的共同根。）
5. **一道從未響過的警報，同沒裝過一樣。** 見到保護計數「0 行」，
   先問「它有沒有真的跑過」。
6. **離線 lint 同執行期不變量擋兩種病，不可互相取代。**
7. **測試不要自己重新實作系統的規則——寫入之後問系統。**
   S03 三輪紅三次（認不出→不合資格→無堂委身分），每次漏一條規則；
   最後用唯讀的 `apiSaveAndConfirmPlan()` 問系統一句就完。
8. **修了碼之後要令改動真的執行過先算修好。**
   「只重跑紅色」跳過綠色情境，令 v2 的修正一次都未跑過就被判失敗。
