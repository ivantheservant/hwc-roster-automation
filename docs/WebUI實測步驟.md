# Web UI 實測步驟

Web UI（網頁版操作介面）到目前為止**從未真正 deploy 過**，只在 Node.js
離線環境測試過純邏輯（純判斷部分，唔涉及真正嘅 Google Sheets／Drive／
MailApp）。呢份文件係俾你 deploy 之後、第一次真正用瀏覽器打開嚟測試
時用嘅步驟指引，用唔熟程式嘅人都睇得明嘅講法。

**核心原則：全程用 `DRY_RUN=TRUE`（測試模式）＋一個你唔怕整亂嘅測試
季度嚟做呢次實測，唔好一開始就用真實季度、更加唔好喺 `DRY_RUN=FALSE`
狀態下試。**

---

## 一、Deploy 之前要確認嘅事

1. **`Config` 工作表**：
   - `DRY_RUN` = `TRUE`（測試模式，唔會真正寄信）
   - `WEBAPP_ENABLED` = `FALSE`（先維持關閉，deploy 完先開）
   - `WEBAPP_ALLOWED_EMAILS` = 只填你自己嘅電郵（先淨係你一個人可以用）
2. **試算表嘅 `appsscript.json`**：`webapp.access` 應該係 `MYSELF`
   （只有部署者本人可以打開網址）——呢個係 Ivan 你自己 deploy，
   `MYSELF` 啱嘅。
3. **準備一個測試季度**：唔好直接用真實季度做第一次測試。可以用
   選單「準備工作 ▸ ⚠️ 新增季度」開一個新嘅測試季度（例如
   `9999T1`），或者揀一個你唔怕整亂、已經有齊資料嘅舊季度。

---

## 二、Deploy 步驟（Ivan 自己在 Apps Script 編輯器操作，本輪指示
禁止由 Claude 執行）

1. Apps Script 編輯器右上角「部署 ▸ 新增部署」。
2. 類型揀「網頁應用程式」。
3. 執行身分：`我`（對應 `appsscript.json` 嘅 `USER_DEPLOYING`）。
4. 存取權限：`只有我自己`（對應 `MYSELF`）。
5. 部署完成後會攞到一個網址，記低嚟但**先唔好打開**。
6. 返去 `Config` 工作表，將 `WEBAPP_ENABLED` 改做 `TRUE`。
7. 現在先打開網址。

---

## 三、測試順序（建議跟返呢個次序，每一步都留意「預期見到咩」）

### 3.1 第一次打開

**預期見到**：頁面標題「粵語堂職事表系統」，上面有個季度下拉選單、
Stage／DRY_RUN 兩個徽章、一排步驟卡片。

**如果見到**：
- 「Web UI 目前已停用」——代表 `WEBAPP_ENABLED` 未開，返去 Config 檢查。
- 「你沒有權限使用這個頁面」——代表你登入嘅 Google 帳號唔喺
  `WEBAPP_ALLOWED_EMAILS`（或者 `SCRIPT_ACCOUNT_EMAIL`）入面，檢查
  你用邊個帳號登入緊瀏覽器。
- **完全空白，只有標題，冇任何季度可揀**——代表 `Quarters` 工作表
  完全冇資料（本輪已經修好呢個情況會顯示明確提示文字，如果你見到
  嘅係真正嘅空白畫面而唔係提示文字，代表修正冇生效，記低回報）。

### 3.2 揀季度、睇步驟卡片

揀返你準備嘅測試季度，睇下五張步驟卡片顯示嘅狀態（可用／已完成／
鎖定）係咪同你喺選單度見到嘅 Stage 相符。

### 3.3 逐一開步驟 2、3、4、5（用測試季度，DRY_RUN=TRUE）

每一步入面嘅畫面文字，跟返選單版本嘅確認視窗核對一次內容係咪一致
（收件人數、版本號、DRY_RUN 狀態等）。**留意每個「確認」畫面撳落
去之後，最終完成畫面嘅統計數字**（寄出／模擬／查無電郵／失敗）。

### 3.4 專門測試「取消」「完成」「關閉」呢類按鈕

**本輪已經修正咗一個問題**：呢類按鈕原本背後嗰個刷新函式完全冇錯誤
處理，如果剛好嗰刻讀取狀態失敗，畫面會靜靜咁乜都冇發生。測試方法：
喺任何一個精靈視窗度撳「取消」或者「完成」，睇下畫面係咪即刻刷新
返最新狀態（步驟卡片、Stage 徽章都要跟住變）。如果撳咗冇反應、或者
狀態明顯係舊嘅，記低回報。

### 3.5 專門測試步驟 4 入面兩個「繼續」按鈕

**本輪已經修正咗另一個問題**：步驟 4 嘅「有未完成事項」畫面同「缺
個人 PDF」畫面入面嗰粒「繼續」按鈕，原本冇錯誤處理，撳落去如果讀取
失敗會靜靜咁冇反應。測試方法：揀一個仍然有 PENDING 申報，或者仍然
缺個人 PDF 嘅測試季度，行到步驟 4，撳呢兩粒「繼續」，睇下畫面有冇
順利去到下一個畫面（正常情況應該好快過渡，唔會卡住）。

### 3.6 手快連撳測試（防止重複觸發）

隨便揀一粒會執行動作嘅按鈕（例如步驟 3「繼續」），**手快連撳兩下**。
預期：第一下撳落去，全部按鈕應該即刻變灰（停用），第二下撳唔到任何
嘢，唔應該觸發兩次動作。如果見到兩次動作都執行咗（例如套用申報
畫面出現咗兩次、或者對話框重疊），記低回報。

### 3.7 中途離開再返嚟測試

行到精靈視窗中間（例如步驟 3 嘅 1/3 驗證結果畫面），直接重新整理
瀏覽器分頁（F5）。預期：頁面重新載入，回到最初嘅季度選擇畫面，冇
半途而廢嘅殘留視窗。之後撳「重新整理狀態」，確認睇到嘅 Stage 同
版本號係最新、正確嘅（呢個對應 `docs/中斷復原指引.md` 講嘅「中途
中斷」情境——Web UI 版本結構上跟選單版本共用同一套後端邏輯，理論上
復原方式一致，但呢個係第一次喺真正瀏覽器環境驗證，值得留意）。

### 3.8 講員與翻譯側邊欄（獨立於五步驟流程，用選單開）

呢個側邊欄**唔經過** Web App 網址，係直接喺試算表選單開嘅
（`準備工作 ▸ 填寫講員與翻譯`），唔受 `WEBAPP_ENABLED` 影響，隨時
可以測試。填一個測試姓名、撳「儲存」，確認職事表格子有更新到。
手快連撳「儲存」測試（本輪已修正：撳落去按鈕會停用，防止重複送出）。

---

## 四、發現異常時即時停止嘅指標

見到以下任何一種情況，**立即停止測試**，唔好再撳任何嘢，先去
`Config` 將 `WEBAPP_ENABLED` 改返 `FALSE`（見下面第五節）：

- `DRY_RUN` 徽章顯示 `FALSE`，但你冇改過（代表 Config 被人改咗，
  或者你自己一開始冇檢查清楚）。
- 步驟 2／4 完成畫面顯示「模式：正式寄出」，但你以為自己仲喺
  DRY_RUN 模式。
- 步驟 2／4 嘅確認畫面出現「⚠️ 偵測到已經有 N 位收件人有紀錄」嘅
  警告，但你確定呢個版本呢個階段係第一次執行（代表警告邏輯本身可能
  有問題，或者代表確實有過中斷——兩種情況都要先停低核查，唔好照撳）。
- 任何一個步驟嘅完成畫面統計數字，同你喺 `SendLog`／`RosterVersions`
  實際睇到嘅唔相符。
- 畫面卡住、按鈕全部停用咗但長時間（超過一分鐘）都冇反應。

## 五、緊急停用

`Config` 工作表將 `WEBAPP_ENABLED` 改做 `FALSE`——即時生效（下次
`google.script.run` 呼叫就會被擋，`doGet()` 亦都會退回顯示停用頁面），
唔需要重新 deploy、唔需要移除部署。呢個係全個 Web UI 安全模型三層
防護入面反應最快嗰一層，見 `docs/系統範圍稽核.md` 嘅「Web UI deploy
前置：三層防護現況」一節。

## 六、測試完成之後

1. 測試季度用完，記得自己判斷要唔要用「維護 ▸ ⚠️⚠️ 重設季度測試資料」
   清理（如果係新開嘅測試季度）。
2. 如果打算開始畀真實幹事用：`WEBAPP_ALLOWED_EMAILS` 要記得加返所有
   應該有權限嘅人；如果日後要畀唔同 Google 帳號登入嘅人（唔止你自己）
   使用，仲要將 `appsscript.json` 嘅 `access` 由 `MYSELF` 改做
   `DOMAIN`——完整風險評估同步驟見
   `docs/系統範圍稽核.md`「`MYSELF` 現在是對的，日後交給幹事要改
   `DOMAIN`」一節。
3. 確認冇問題之後，先至可以考慮將真實季度嘅 `DRY_RUN` 改做 `FALSE`
   ——呢一步嘅風險同建議順序另見「維護 ▸ 上線前檢查」嘅「建議上線
   切換順序」。
