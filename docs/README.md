# docs/ 文件索引

呢個資料夾入面每份文件都有唔同嘅讀者同用途。下面按讀者分組，幫你快啲
搵到啱睇嗰份，唔使成份成份咁揭。

## 幹事日常操作睇呢幾份

- **[`幹事操作說明.md`](幹事操作說明.md)**——最主要嗰份，五個步驟點做、
  `Requests` 點填、硬規則違反點算、選單完整結構，日常操作有問題先睇
  呢份。
- **[`中斷復原指引.md`](中斷復原指引.md)**——執行到一半失敗、唔知做咗
  未、唔知可唔可以重新撳掣，睇呢份。逐步驟列咗「症狀 → 點知係呢個
  情況 → 應該點做」。
- **[`排表規則.md`](排表規則.md)**——教會定下嘅排表規則同每一條喺系統
  入面點樣落實：身分名單（堂委／執事）、個人崗位限制、堂委集中四崗位、
  每年四次固定合堂。**換屆嗰陣一定要睇**——入面講咗「填結束日、唔好
  刪除整行」呢個好易做錯、做錯咗會令舊季度全部變違規嘅重點。

- **[`電郵範本樣本.md`](電郵範本樣本.md)**——收件人**實際會收到嘅信**
  長成點（主旨＋內文全文），用虛構資料渲染出嚟。**真正開始寄信
  （`DRY_RUN=FALSE`）之前應該逐封讀一次**——之前系統模擬寄出過幾十封，
  但由頭到尾冇人真正讀過內文。入面亦都列咗覆核時搵到嘅兩個問題同修正，
  以及 Ivan 要自己喺工作表做嘅兩件事。

- **[`季度重置與重生成.md`](季度重置與重生成.md)**——一個季度俾人用嚟做過
  測試，想清乾淨再用最新演算法重新生成一份時睇呢份。逐步講埋「邊啲嘢
  系統唔會幫你清、要自己處理」（`Unavailable` 同 `Eligibility` 嗰兩項）。
- **[`首次上線檢查清單.md`](首次上線檢查清單.md)**——**第一次真正用系統
  出一季職事表**（即係義工真係會收到信）之前到之後，逐步要做嘅嘢。
  每一步都列咗誰做、喺邊度做、點確認做啱咗、邊幾步唔可逆同點補救，
  仲有以正式發出日往前推嘅時間表。

- **[`個人連結頁面樣本.md`](個人連結頁面樣本.md)**——義工打開個人專屬
  連結會睇到嘅**實際頁面完整 HTML 輸出**，涵蓋正常／無效 token／
  季度不存在／零派工四種情況，用虛構資料實際渲染出嚟。**新增
  access=ANYONE 部署之前應該睇一次**——附完整安全覆核結論（有冇 PII
  洩漏、錯誤訊息夠唔夠中性、匿名訪客會唔會被拒絕）。
- **[`ICS檔樣本.md`](ICS檔樣本.md)**——附加喺電郵入面嘅 `.ics` 日曆檔
  **實際完整內容**，用虛構資料實際產生出嚟，附 RFC 5545 格式、UID／
  SEQUENCE 跨版本行為、紐西蘭夏令時間轉換、iPhone 相容性嘅逐項覆核
  結論。**真正寄出帶附件嘅信之前應該睇一次**。
- **[`ICS實測步驟.md`](ICS實測步驟.md)**——ICS 日曆檔係四個新功能之中
  唯一未喺真機驗證過嘅一個。呢份文件講點用「測試工具 ▸ 寄送單一
  ICS／highlight 測試信」寄一封只有自己會收到嘅測試信，喺 iPhone 上
  實際打開核對。**真正寄出帶 ICS 附件嘅信之前應該做一次**。
- **[`講員翻譯獻花填寫.md`](講員翻譯獻花填寫.md)**——講員、翻譯、獻花
  三個崗位系統永遠唔會自動排人，每季都要人手填。呢份文件講點用側邊欄
  工具一次過填晒，以及獻花點樣可以留空。
- **[`2026T4彩排步驟.md`](2026T4彩排步驟.md)**——2027T1 正式上線前**唯一
  一次完整彩排**嘅步驟清單，由清理測試殘留到走完五階段流程，逐步寫明
  撳邊個選單項、輸入乜、預期見到咩數字。**準備彩排 2026T4 之前應該
  由頭跟到尾睇一次。**

## Deploy／安裝相關操作，一次性動作先需要睇

- **[`WebUI實測步驟.md`](WebUI實測步驟.md)**——Web UI（網頁版介面）
  第一次真正 deploy 之後嘅實測步驟。日常操作用唔到，deploy 嗰陣先睇。
- **[`Trigger安裝步驟.md`](Trigger安裝步驟.md)**——安裝「自動排程」
  之前要確認嘅事、安裝之後點觀察。安裝一次之後除非要重新安裝，
  否則唔需要再睇。
- **[`移交清單.md`](移交清單.md)**——系統要交俾第二個人負責時先要睇，
  逐項列咗邊啲嘢會自動跟住轉、邊啲唔會，日常操作完全用唔到。

## 開發者／對話另一邊的 Claude 睇呢份

- **[`系統範圍稽核.md`](系統範圍稽核.md)**——**永久維護**嘅技術稽核
  記錄，每一輪開發都會更新。內容包括：系統範圍需求逐項現況、已知的
  設計取捨、待覆核決策清單、各輪稽核發現的問題與修正、完成度評估。
  **想快速知道「排表演算法有冇經過驗證」「有冇找到過真實 bug」，
  直接睇最後一節「第十四輪批次」。**
  存在嘅理由：`HANDOFF.md` 同 `docs/開發歷程.md`（下面會講）都唔公開，
  只有喺呢部電腦跑 `claude` 先讀得到——如果對話喺另一個地方繼續
  （網頁版、另一台機、或者淨係睇得到呢個 GitHub public repo），嗰邊嘅
  Claude 完全冇辦法讀到嗰兩份文件，只能夠靠呢份。**如果你係第一次
  接手呢個專案嘅 Claude，建議由呢份文件開始睇。**
- **[`GoogleSheetsAPI限制.md`](GoogleSheetsAPI限制.md)**——寫緊會重寫
  已存在工作表版面（合併／凍結／欄闊）嘅程式碼之前應該睇一次。列出
  已經確認過嘅 Google Sheets API 結構性限制（例如合併唔可以跨越凍結
  界線、`clear()` 唔會解除合併／歸零凍結狀態），逐條寫明「限制內容 /
  出事情況 / 點樣避免」，以及 mock 測試層（`tests/helpers/sheet_mock.js`）
  對呢啲限制嘅覆蓋程度。

## 唔公開、只有本機睇得到（`.gitignore` 排除，唔會出現喺 GitHub 上）

- **`HANDOFF.md`**（repo 根目錄，唔喺 `docs/` 入面）——精簡版現況記錄，
  環境事實、每一輪批次嘅摘要、待覆核決策嘅索引。**完整內容已經搬咗去
  `系統範圍稽核.md`**，呢份淨係留低「呢部機先需要知」嘅嘢（環境設定、
  逐輪操作紀錄嘅索引）。
- **`開發歷程.md`**——一字不刪嘅逐階段完整開發紀錄，跨越全部歷史批次。
  之所以唔公開：對外部讀者冇實質價值（要核實程式碼直接睇 `src/` 就夠），
  公開純粹係風險、冇對應收穫。內容按時間倒序（最新嘅決定排最上面）。
