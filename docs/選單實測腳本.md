# 選單實測腳本

**目的**：把「82 個選單項目當中只有約三成真正在瀏覽器按過」這件事，
變成一條照著做就做得完的路線。

這是目前距離上線**最大的未知數**。第十九輪批次一天之內就在真實環境
撞到五個問題，而 60 個離線測試檔全部 PASS——證明「測試全綠」跟
「工具真的用得到」是兩件事。Claude 按不到按鈕，但可以讓你按得有效率。

> ⚠️ **這份文件不會安排任何會清走 2026T4 現有資料的步驟。**
> 2026T4 目前的版本、SendLog、RosterPDF 是第十九輪修正之後要用來驗證的
> 實測基準，整份腳本都當它是唯讀的。

## 怎麼用這份文件

- **每一段都可以獨立停下來。** 每段開頭有預估時間，按你手上有多少時間挑。
- **「見到什麼就代表有問題」那一欄是重點。** 如果只寫「應該正常」，
  那一項等於沒測——所以每一項都寫了具體數字或字句。
- **不可逆的動作全部集中在最後（第 F 段）**，不會混在主線裡面。
  主線（A–E 段）任何一步都不會破壞現有資料。
- 撞到問題就停手，把**畫面截圖 + 你輸入了什麼**記下來。
  第十九輪那五個問題，全部都是靠「截圖 + 實際輸入」才定位到的。

### ⚠️ 一個必須誠實講的落差

你可能會預期「2026T4 五階段今日全部跑過，覆蓋率應該大升」。
**實際上升幅很小，而且有一部分反而要重測**，理由有兩個：

1. **再跑一次同樣的五個步驟，增加的是信心，不是覆蓋率。**
   分子還是那五項，只是換了一個季度。這仍然有價值（2026T4 有特殊主日、
   身分規則等 2027T1 沒有的條件），但它不會讓「另外 47 個沒按過的項目」
   變成按過。
2. **第十九輪改動了步驟 3、4、5 的行為**，所以這三項先前的「已實測」
   只對舊行為有效。它們在下面第 B 段要重新走一次。

誠實的數字：**約 23 / 82 ≈ 28%**。

## 撞到問題的時候

記下三樣東西就夠：

1. **你在哪一項、輸入了什麼**（一字不改地抄下來——第十五輪那個 bug
   就是全形字元造成的，肉眼看不出來）
2. **畫面截圖**（尤其是錯誤訊息全文）
3. **當時的 Stage 與版本號**（查看 ▸ 匯出關鍵狀態）

第十九輪那五個問題全部是靠這三樣定位到的。特別是階段 A 那個——
你說「grid 顯示確實變咗（我截圖確認過）」，那句話直接把範圍縮到
「顯示是對的，讀取是錯的」，省掉大半天。
