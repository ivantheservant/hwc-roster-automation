# 系統移交清單

呢個系統而家全部綁定喺「開發帳戶」（負責開發呢個系統嗰個 Google 帳戶）
名下。日後要交俾負責日常操作嘅人（下面統稱「角色帳戶」——可以係幹事
自己嘅帳戶，或者專門開嚟做呢件事嘅教會帳戶，睇你哋點決定），有幾樣
嘢**唔會自動跟住轉**，要逐項人手處理。呢份文件唔會出現任何真實帳戶、
Script ID、試算表 ID，全部用代稱講。

**先講結論（E3 稽核）：程式碼本身完全冇寫死任何人嘅身分**——全部
「邊個喺操作」都係靠 Google 提供嘅 `Session` API 即時讀取（自動跟住
實際登入嗰個帳戶變），需要記住身分嘅地方（例如邊個帳戶算「系統帳戶」、
通知寄去邊個信箱、Web UI 畀邊幾個人用）全部都係 Config 工作表入面
可以自己改嘅值，唔係寫死喺程式碼。**即係話：移交呢件事完全唔需要改
任何程式碼，只需要處理下面呢幾項平台層級嘅設定同埋幾個 Config 值。**

---

## 一、逐項要處理嘅嘢

### 1. clasp 登入帳號（開發用，日常操作唔會用到）

`clasp` 呢個工具用嚟由本機推送程式碼上 Apps Script，登入資訊存喺
呢部電腦本身（`.clasprc.json` 呢類本機檔案，唔喺 git repo 入面）。

**移交要做嘅**：如果角色帳戶都需要有能力推送程式碼改動（例如你想
教識佢哋自己維護），佢哋需要自己嘅電腦上跑 `clasp login`，並且喺
Apps Script 編輯器度（`script.google.com`）將呢個 Apps Script 專案
加佢哋做協作者（Apps Script 專案自己有一套共用設定，同 Google Sheet
嘅共用設定係兩回事，唔會自動同步）。

**做漏咗嘅後果**：角色帳戶完全冇辦法改程式碼，只能夠用選單／Web UI
操作現有功能。如果佢哋唔需要改程式碼（大部分幹事嘅日常操作都唔需要），
呢一項可以唔做。

### 2. Web App 部署身分

`appsscript.json` 嘅 `executeAs: "USER_DEPLOYING"` 代表 Web App
**成個運作嘅執行身分，係嗰個當初撳「部署」嗰個帳戶**，唔理邊個經
瀏覽器打開個網址——全部操作都算係嗰個部署者本人做嘅（Session 讀到嘅
身分、Apps Script 執行配額，全部算喺佢頭上）。

**移交要做嘅**：如果想角色帳戶成為真正嘅執行身分（唔係得個殼畀佢用），
要用角色帳戶登入 Apps Script 編輯器，重新做一次「部署 → 新增部署」
——單純改 `appsscript.json` 嘅內容唔會令執行身分改變，一定要嗰個
帳戶親自部署一次。

**做漏咗嘅後果**：Web App 表面上畀緊角色帳戶用，但背後全部操作
（包括寫入試算表、產生 PDF）實際上都用緊開發帳戶嘅身分執行。如果
開發帳戶嘅權限日後被收回或者停用，Web App 會完全停止運作，而且冇
任何預警。

### 3. Trigger（自動排程）擁有者

邊個帳戶執行「安裝自動排程」，個 trigger 就綁定嗰個人嘅授權去執行。
呢個同上面第 2 點係獨立分開嘅——就算部署身分已經轉咗，trigger 唔會
自動跟住轉。

**移交要做嘅**：用角色帳戶執行選單「⚠️⚠️ 自動排程 ▸ ⚠️⚠️ 移除自動
排程」，然後再用同一個角色帳戶「⚠️⚠️ 安裝自動排程」一次。

**做漏咗嘅後果**：如果原本安裝 trigger 嗰個帳戶（例如開發帳戶）嘅
Google 帳戶日後被停用、或者權限被收緊，trigger 會**靜靜咁停止運作**
——Apps Script 唔會主動通知任何人，你只會發現「點解個季度冇自動生成
初稿」先發現原來自動排程已經停咗好耐。呢個係最容易被忽略、後果卻
可能最遲先發現嘅一項，見 `docs/Trigger安裝步驟.md`。

### 4. Google Drive 檔案擁有權（RosterPDF 資料夾）

Config 嘅 `ROSTER_DRIVE_FOLDER_ID` 指向嘅資料夾（存放全部 PDF），
以及入面全部已經產生嘅 PDF 檔案，擁有者通常係第一個建立呢啲嘢嗰個
帳戶。

**移交要做嘅**：喺 Google Drive 度決定以下兩個做法其中一個（**要
明確揀一個，唔好含糊**）：
- **(a) 轉移擁有權**：將個資料夾（連同入面全部檔案）嘅擁有者轉俾
  角色帳戶——Google Drive 支援整個資料夾一次過轉移擁有權。
- **(b) 保留擁有權、只畀編輯權限**：資料夾繼續留喺開發帳戶名下，
  但畀角色帳戶「編輯者」權限——角色帳戶一樣可以正常用，但長遠嚟講
  仍然依賴開發帳戶嘅 Google 帳戶持續存在同有效。

**做漏咗嘅後果**：如果乜都冇做（角色帳戶連編輯權限都冇），角色帳戶
執行「產生個人 PDF」呢類會寫入呢個資料夾嘅操作會直接失敗（冇權限）。

### 5. Google 試算表本身嘅擁有權

呢個先係最根本嗰一項——Google Sheets 嘅「擁有者」呢個身分有特殊
權力，**擁有者永遠可以編輯任何受保護嘅工作表，呢個係 Google 平台
本身嘅限制，程式碼冇辦法覆蓋**（見 `RosterWriter.gs` 嘅 `protectV0()`
註解）。即使你將 `SCRIPT_ACCOUNT_EMAIL` 呢個 Config 值改做角色帳戶、
`protectV0()` 明確淨係將編輯權留低畀嗰個帳戶，只要試算表擁有者仍然
係開發帳戶，開發帳戶依然可以繞過保護直接編輯 v0（因為佢係擁有者，
唔受保護設定限制）。

**移交要做嘅**：喺試算表右上角「共用」度將擁有權轉俾角色帳戶（Google
Sheets 支援轉移擁有權，唔需要整份重新建立）。

**做漏咗嘅後果**：表面睇落已經完成晒移交，但開發帳戶其實仍然對整份
試算表有終極控制權（包括繞過 v0 保護、刪除工作表等）。如果移交嘅
原意包括「唔想開發帳戶再有能力改動資料」，漏咗呢一步等於冇做到。

### 6. Script Properties（PDF 批次進度，一般唔需要處理）

`PropertiesService.getScriptProperties()` 存住少量暫存資料（個人 PDF
批次產生／步驟 5 重發批次嘅進度，見 `docs/中斷復原指引.md`），呢啲
屬於 Apps Script **專案本身**，唔綁定任何個人帳戶，轉移專案擁有權
（或者共用設定）時會自動跟住走，唔使特別處理。**唯一要注意**：如果
轉移嗰刻剛好有未完成嘅 PDF 批次（例如「PDF 尚未完成」畫面），建議
等佢做完先轉移，或者接受轉移之後可能要重新開始嗰個批次。

### 7. Config 工作表入面同身分有關嘅值（純資料，改完即生效，唔需要改程式碼）

移交前後記得更新以下幾個 Config 值，改做角色帳戶／新負責人嘅電郵：

- `SCRIPT_ACCOUNT_EMAIL`——Web UI 白名單留空時嘅退回對象、`protectV0()`
  保留邊個可以編輯 v0。
- `MAIL_ADMIN_NOTIFY`——自動排程嘅通知（GENERATE 完成、REMIND 提醒）
  會寄去呢個信箱，唔改嘅話新負責人完全收唔到呢類通知。
- `WEBAPP_ALLOWED_EMAILS`——Web UI 嘅使用白名單，記得加返新負責人嘅
  電郵（唔改嘅話佢哋打開網址只會見到「你沒有權限使用這個頁面」）。

### 8. GitHub public repo（如果都要一併移交）

呢個 repo 目前掛喺開發帳戶嘅 GitHub 帳號名下。如果打算連呢部分都
移交，可以用 GitHub 本身嘅「Transfer ownership」功能，或者加新帳號
做協作者。呢部分同試算表操作完全獨立，唔影響系統實際運作（程式碼
一定要 `clasp push` 先會真正生效，git repo 本身只係存放原始碼副本，
方便公開審閱）。

## 二、建議嘅移交順序

1. 先確認全部要轉移嘅擁有權物件（試算表、Drive 資料夾）都搞掂
   ——呢兩項係最根本，其他項目都建立喺呢兩項之上。
2. 更新 Config 嘅 `SCRIPT_ACCOUNT_EMAIL`／`MAIL_ADMIN_NOTIFY`／
   `WEBAPP_ALLOWED_EMAILS` 三個值。
3. 用角色帳戶重新部署 Web App（如果有用緊 Web UI）。
4. 用角色帳戶重新安裝 trigger（如果有用緊自動排程）——記得先移除
   舊嗰個，避免同時有兩個 trigger 一日執行兩次。
5. 確認角色帳戶可以正常執行選單操作、Web UI、收到通知信。
6. 決定要唔要處理 clasp／GitHub 呢兩項開發相關嘅存取權（睇角色帳戶
   使用者需唔需要改程式碼）。

## 三、如何驗證移交已經完成

1. 用角色帳戶登入，執行「🩺 全面體檢（唯讀）」，確認全部檢查正常。
2. 用角色帳戶執行「檢查自動排程條件（唯讀）」，確認能夠正常讀取
   （代表權限設定生效）。
3. 執行一次選單操作（例如「產生個人 PDF」），確認角色帳戶對 Drive
   資料夾有寫入權限。
4. 如果有用 Web UI，用角色帳戶（或者你想開放使用嘅其他人）打開網址，
   確認睇到嘅係正常介面，唔係「已停用」或者「冇權限」。
5. 檢查試算表右上角「共用」設定，確認擁有者已經係角色帳戶（如果
   移交原意包含呢一步）。
