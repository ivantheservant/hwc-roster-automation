## 第 5 節　補電郵之後重發（本輪最重要）

> 排在前面做。這一節是第三十三輪階段 A 修正的唯一現場驗證。

**目的**：證明一個「正式發出時查無電郵、之後才補上電郵」的人，
真的會收到他的第一封信。

修好之前的行為：這個人會被記成 `SKIPPED_UNCHANGED`（內容沒變而略過），
**第一封信永遠寄不出去，而且沒有任何錯誤訊息**。
修好之後：他會被記成模擬成功（`DRY_RUN`）。

**前置條件**：
- 第 0 節做完，`2027T4` 確認在 `OFFICIAL_SENT`
- `DRY_RUN` ＝ `TRUE`（今日全程）

### ⚠️ 這一節會改動 NameMapping 的真實資料

所以程序寫成可還原的。**節末有一步是把它改回去，那一步不可以跳過。**

### 逐步操作

> ⚠️ **這一節不寫死是哪一位義工。** 這份文件在公開 repo 裡，
> 真實的 PersonID 與姓名都不可以寫進去（`scan-staged-secrets.js` 會擋）。
> 下面一律叫他「**測試對象**」——第 1 步會教你怎樣挑。
> 挑的時候把他的 PersonID 抄在自己的記事本上，不要寫進任何會進 git 的檔案。

**第 1 步——挑一位測試對象，並記低原狀。**

1. 開 `SendLog` 工作表，篩 `QuarterID` ＝ `2027T4`、`Stage` ＝ `OFFICIAL`、
   `Status` ＝ `SKIPPED_NO_EMAIL`。
2. 預期見到 **7 行**（2026-08-20 實測的數字）。
3. 從這 7 位之中**隨便挑一位**做測試對象，把他的 `PersonID` 抄在記事本上。
4. 開 `NameMapping`，找那一行，確認 `Email` 欄是**空白**。

> 如果那一欄不是空白，代表資料已經改過。換另一位，或者**停在這裡**回報。
>
> 為什麼是「隨便挑一位」而不是指定某一位：這樣寫的話，就算日後有人幫其中
> 幾位補上了電郵，這一節照樣跑得動——不會因為指定那一位剛好已經有電郵而卡住。

**第 2 步——填入測試地址。**

在**測試對象**的 `Email` 欄填入**你自己的信箱，加一個一望就知是測試的後綴**：

```
<你的帳號>+rostertest@<你的網域>
```

加號後綴會送到你同一個信箱（Gmail 與 Google Workspace 都支援），
而且一望就知道那是測試填進去的，不會被誤當成那位義工真正的電郵。

> 今日 `DRY_RUN` ＝ `TRUE`，所以其實不會真的寄出。填一個真地址是為了萬一
> 將來有人在 `DRY_RUN` ＝ `FALSE` 時重跑這一節，信也只會寄到你自己。

**第 3 步——撳步驟 5。**

1. 開幹事 Web UI（`/exec` 那條網址）。
2. 右上角季度選 **2027T4**。
3. 區一第四粒掣「**改動後重發**」，撳「**重發**」。
4. 看確認畫面。

**第 4 步——看確認畫面的名單。**

預期：**名單上只有測試對象一個人**，而且旁邊標住「這是第一次通知」之類的字眼
（因為他的派工內容一格都沒有改，他上榜的原因是「補了電郵」，不是「有改動」）。

**第 5 步——確認送出。**

撳確認。等它跑完（幾秒）。

**第 6 步——查 SendLog。**

開 `SendLog` 工作表，找最後那一批 `Stage` ＝ `RESEND` 的紀錄。

**第 7 步——再撳一次步驟 5。**

回 Web UI，再撳一次「改動後重發」。

### 預期見到什麼

| 步 | 預期 |
| --- | --- |
| 4 | 名單只有測試對象一人 |
| 5 | 完成對話框說「1 位」之類，沒有錯誤 |
| 6 | `SendLog` 有一行：`PersonID` ＝ 測試對象、`Stage` ＝ `RESEND`、**`Status` ＝ `DRY_RUN`** |
| 6 | 另外 6 位查無電郵的人**在這一批 RESEND 紀錄裡完全沒有出現** |

| 7 | 這一次說「沒有人需要重發」（`NO_CHANGES`），測試對象不再出現 |

> ⚠️ 第 6 步那兩行「沒有出現」是正確的，不是漏了。
> 系統只會嘗試「真的需要通知」的人——內容沒變又沒有補電郵的人根本不會被碰，
> 所以 `SendLog` 不會有他們這一批的行。

## 第 7 節　ICS 附件時間

### 逐步操作

2. 選單 ▸ **測試工具** ▸ **⚠️ 寄送單一 ICS／highlight 測試信**。

4. 執行。
5. 開你的信箱，找那封測試信。
6. **開附件那個 `.ics` 檔**（用記事本開，或者直接匯入日曆）。

### 預期見到什麼

- `.ics` 檔裡的 `DTSTART` 時間 ＝ Config 那一格的值（換算成當地時間之後）
- 匯入日曆之後，事件的開始時間就是崇拜開始時間，**不是 00:00、不是 12:00**

### 不符預期代表什麼

| 見到 | 代表 | 嚴重程度 |

| `DTSTART` 是 00:00 | 時間欄讀成空白然後退回午夜 | 高——就是那個舊 bug 復發 |
| `DTSTART` 比預期差幾個鐘 | 時區換算問題 | 中 |
| 信收不到 | `DRY_RUN` ＝ `TRUE` 之下**這一封仍然應該真的寄出**（它是測試信）；收不到代表寄送本身有問題 | 中 |

### 這一項 Claude 讀不讀得到
