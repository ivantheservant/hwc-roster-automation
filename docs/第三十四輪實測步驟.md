## 第 2 節　新版本的 PDF 圖例

**目的**：證明經「儲存並確認」建立的版本，格子分類沒有壞。

修好之前：`2027T3 v2` 的完整版 PDF 圖例把 **79 格**報成「系統未能安排」，
而正確答案是 **0**。算術直接指出成因——273 總行 − 194 有派人 = 79，
即是**沒有做分類**，把所有沒有派人的格整批倒進最後一個桶（甲5）。

⚠️ 這份 PDF 是寄給每一位義工的附件。

**前置條件**：第 1 節做完，有一個新版本。

### 逐步操作

1. 區四 ▸「匯出職事表 PDF」，季度 `2027T3`、版本留空（＝最新版）。
2. 開產生出來的 PDF，翻到圖例那一段。
3. 順手也匯出 **v0**（第一版，由系統自動生成那個）的 PDF 作對照。

### 預期見到什麼

新版本的圖例應該是這種形狀：

```
（姓名）　　系統自動安排，已排定人選　　194 格
待確認　　　此崗位不由系統自動安排　　　 39 格
—　　　　　這一週不設此崗位　　　　　　 40 格
特殊主日　　這一週有特別安排　　　　　　  0 格
⚠ 未能安排　系統找不到合資格而當日又有空的人　0 格
```

關鍵是三件事：

- **「未能安排」是 0**（或者一個很小的數，總之不是「全部沒有派人的格」）
- **「待確認」和「—」不是 0**
- 五個數加起來 ＝ 總格數，而且**跟 v0 那份的分佈一樣**
  （申報只改人，不應該改變任何一格的「跳過原因」）

### 不符預期代表什麼

| 見到 | 代表 | 嚴重程度 |
| --- | --- | --- |
| 「未能安排」＝ 總格數 − 有派人的格 | 甲5 沒有生效，分類仍然整個遺失 | 高——這份 PDF 會寄給全體義工 |
| 「待確認」和「—」都是 0 | 同上 | 高 |
| 新版本的分佈跟 v0 不一樣 | `ruleFlags` 有被改動到，要查是哪幾格 | 中 |

### 要回報什麼

新版本和 v0 兩份 PDF 的圖例那五個數字（**貼文字就可以，不用截圖**）。

### 這一項 Claude 讀不讀得到

`RosterAssignments` 的 `RuleFlags` 欄我讀得到，可以自己算出五個桶。
**PDF 本身讀不到**——但如果你把五個數字貼回來，我可以對照我算出來的。

## 第 3 節　NEEDS_INPUT 不會鎖死

**目的**：證明一筆「系統看不懂」的申報不會令「正式發出」永遠灰。

訊息叫幹事「先撳儲存並確認」，撳幾多次都處理不完（甲3）。
現場是靠人手到 `Requests` 刪走那兩行才能繼續。

**前置條件**：第 1 節做完。

   - `RequestType` ＝ `指定服侍`
   - `RequestID`、`Status` 留空
2. 回 Web UI，重新整理。
3. 看區一第一粒掣的說明文字。
4. 看區一第三粒掣「正式發出給全體」是不是灰的。

## 第 5 節　核對職事表跟上限比

**目的**：證明「主席與報告同一人」那一項不再跟 63% 歷史基準比。

63% 是**還沒有身分規則**的年代由 78 週歷史算出來的，描述一個已經不存在的世界。
拍板要改是很早之前的事，但當時只改了「軟規則實測量度」——
**而幹事日常會撳的正是「核對職事表」**（丙1）。

**前置條件**：`2027T3` 有版本。

### 逐步操作

1. 區四 ▸「核對職事表」，季度 `2027T3`。
2. 看報告第 2 節「主席與報告同一人的週數比例」那一行的**第三欄**（目標）。
3. 再跑一次選單 ▸ 查看（唯讀，只寫 Diagnostics）▸「軟規則實測量度（唯讀）」。
4. 對照兩邊講同一件事的措辭。

### 預期見到什麼

第 2 步那一欄應該是這種形狀：

```
XX.X% ± 5.0%（本季理論上限；歷史基準 63.0% 只供參考）
```

**不應該**再是 `63.0% ± 5.0%`。

第 4 步：兩個工具對「跟什麼比」的講法應該一致——都說是跟「本季理論上限」比。

> 如果系統算不出上限（規則未設定之類），會退回跟歷史基準比，
> 那時第三欄會寫「（歷史基準；本季理論上限算不出，這是退回的做法）」
> ——**那也是正確的**，關鍵是它有明講自己在跟什麼比。

### 不符預期代表什麼

| 見到 | 代表 |
| --- | --- |
| 第三欄仍然是 `63.0% ± 5.0%` 而且沒有任何說明 | 丙1 沒有生效 |
| 兩個工具講法不一樣 | 兩邊又各寫了一份（這正是要避免的） |
| 最後那個 TRUE/FALSE 看起來跟新的目標對不上 | 判斷沒有跟著改，只改了顯示 |

### 要回報什麼

「核對職事表」第 2 節那一行的**全部四欄**（逐字），
以及「軟規則實測量度」第 1 項的對應那一行。

### 這一項 Claude 讀不讀得到

**讀得到，不用截圖。** 兩個工具都會寫入 `Diagnostics`。

**預計需時**：15 分鐘。

## 一項未修的資料事項（不是 bug，要 Ivan 拍板）

`SpecialSundays` 的 **`2027T3-MISSION`**（2027-08-29 宣教月合堂）
`SkipPostIDs` 欄是**空白**，所以系統照樣派了領詩和司琴。

這不是程式問題——系統忠實地照住那一格的內容做事。
問題是**那一格應該填什麼，只有你決定得到**。

同類的還有：

| 特別主日 | `SkipPostIDs` 現況 |
| --- | --- |
| `2027T3-MISSION`（2027-08-29 宣教月合堂） | 空白 |
| `2027T1-EASTER` | 空白（同一個待決事項） |
| 2026T4 那個合堂主日 | 當時填了 `WORSHIP,PIANO` |

**要決定的是**：合堂主日那一天，領詩和司琴是不是由對方堂會負責？
是的話就照 2026T4 的做法填 `WORSHIP,PIANO`（或者你決定的那幾個崗位）；
